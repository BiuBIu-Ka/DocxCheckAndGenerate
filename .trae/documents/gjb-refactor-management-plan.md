# 军工软件文档智能编制与审查平台 - 功能深化与管理化重构计划

## 一、 摘要 (Summary)
本计划旨在将平台从“单次工具模式”重构为“文档生命周期管理模式”。通过建立完善的文档 CRUD（增删改查）体系，将编制、生成、审查等功能对接到统一的文档列表。同时，将“知识库”功能实体化，支持规则与术语的在线维护，并新增系统帮助页面以提升用户体验。

## 二、 核心重构目标 (Core Objectives)

### 2.1 文档管理中心化 (CRUD)
- **文档列表**: 实现一个类似项目管理系统的列表页，支持按项目、类型、状态（草稿/生成中/审查中/已完成）进行筛选。
- **编制工作台**: 每一个文档项进入后，是一个集成了“在线编辑、AI 生成、实时审查、导出”的工作台，而不是散乱的生成页面。
- **持久化**: 所有的编制过程、生成的草稿、审查的问题清单全部持久化到 SQLite 数据库。

### 2.2 知识库实体化与开放
- **规则维护**: 将原有的 YAML 静态规则开放为 UI 维护界面，支持新增、修改、停用 GJB 审查规则。
- **术语管理**: 支持用户自定义术语基线（标准名、别名、禁用词）。
- **模板配置**: 支持在线查看和管理 Word 模板的章节骨架。

### 2.3 系统引导与帮助
- **帮助中心**: 新增页面说明 GJB 438B 的基本要求、平台的使用流程（导入模板 -> 编制 -> 审查 -> 导出）。

## 三、 详细变更方案 (Proposed Changes)

### 3.1 后端重构 (FastAPI + SQLAlchemy)
- **数据库模型更新 (`models.py`)**:
    - `Document`: 存储标题、项目、类型、状态、全文 Markdown/JSON 内容。
    - `GjbRule`: 存储规则详情，替代静态 YAML。
    - `TermBase`: 存储术语库条目。
- **API 接口新增**:
    - `/api/documents`: 全套 CRUD 接口。
    - `/api/knowledge/rules`: 规则管理接口。
    - `/api/knowledge/terms`: 术语管理接口。
- **逻辑集成**: 修改 `GenerationOrchestrator` 和 `ReviewOrchestrator`，使其接收 `document_id` 并将结果写回数据库。

### 3.2 前端重构 (Vue 3 + Ant Design Vue)
- **页面重组**:
    - `DocumentListPage.vue` (新增): 文档中心列表。
    - `DocumentWorkspacePage.vue` (由 `GeneratePage` 升级): 文档编制工作台。
    - `KnowledgeBasePage.vue` (重写): 从展示统计数据改为管理规则与术语。
    - `HelpPage.vue` (新增): 系统帮助文档。
- **组件优化**:
    - 增加文档状态标签（Tag）。
    - 实现文档搜索与分页。

## 四、 验证步骤 (Verification Steps)
1. **列表验证**: 创建一个新文档，验证是否在列表中正确显示。
2. **编制验证**: 进入该文档的工作台，修改内容并保存，刷新页面确认内容不丢失。
3. **知识库验证**: 在 UI 上新增一条“禁用术语”，并在文档审查中验证该术语是否被正确拦截。
4. **帮助页面**: 确认帮助中心内容清晰易懂。
