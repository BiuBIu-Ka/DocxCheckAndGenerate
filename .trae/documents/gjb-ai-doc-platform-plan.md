# 基于大模型与GJB规则引擎的军工软件文档智能编制与审查平台实施计划

## 一、Summary

本计划面向“基于大模型与GJB规则引擎的军工软件文档智能编制与审查平台”完整项目实现，目标是在涉密本地部署场景下，建设一套以 Electron 桌面端为主、Vue 为前端技术栈、覆盖文档生成、文档审查、整改闭环、知识沉淀与审计管理的端到端系统。

本次规划按以下已确认决策展开：

- 交付目标：不是竞赛书润色，而是面向真实落地的功能点与实施计划。
- 建设范围：端到端平台。
- 部署约束：本地涉密部署。
- 首版重点：优先落地“生成 + 审查闭环”。
- 文档范围：首版即覆盖全类型文档，包括需求规格说明书、设计说明书、测试说明书、电子交互手册/用户手册、审查记录等。
- 使用形态：Electron 桌面应用为主，内嵌 Vue 前端界面。
- 前端技术：Vue 3 + TypeScript + Ant Design Vue。
- 验收导向：既可竞赛演示，也具备工程可交付性。
- 规则体系：GJB 审查规则采用配置化规则库。
- 模型路线：单 32B 主模型 + 工具链，支持可配置模型接入，兼容 Ollama / OpenAI 兼容接口 / DeepSeek 等。
- 知识底座：纳入现有规范、模板、术语库、历史文档和审查意见资产。

## 三、Assumptions & Decisions

### 3.1 业务假设

- 平台服务对象包含：文档编制人员、项目经理、审查专家、质量人员、系统管理员。
- 平台运行于军工内网或隔离网，不依赖公网。
- 文档输入来源包括：已有 Word/PDF/Markdown 文档、模板文件、历史文档资产、术语库、规则库、界面截图材料。
- 审查输出形式包括：问题清单、定位信息、整改建议、审查报告、闭环状态记录。

### 3.2 核心设计决策

- 采用“Electron 桌面壳 + Vue 前端 + 本地/内网后端服务”的混合架构，兼顾桌面工具调用能力与统一业务界面。
- 采用“主模型 + 规则引擎 + 知识检索 + 文档解析工具链”的组合方案，而非纯大模型方案。
- 采用模型网关抽象，默认接入本地主模型，同时支持兼容式模型切换。
- GJB 规则按“文档类型 -> 章节结构 -> 格式规范 -> 术语规范 -> 图表规范 -> 一致性规范 -> 审查建议模板”进行配置化组织。
- 采用“生成即审查、审查可整改、整改可复核”的闭环流程。
- Electron 主进程负责截图、文件系统访问、系统级能力调用，渲染进程负责业务交互界面。
- 首版优先覆盖文档生成与审查主链路，并同步纳入“截图上传 + 桌面截图采集”基础能力；二期再强化自动截图编排、UML/流程图自动生成、跨版本对比等增强能力。

### 3.3 非目标约束

- 首版不以复杂工作流引擎为重点，先采用轻量任务流转模型。
- 首版不追求全量自动化替代人工审查，保留人工复核与问题确认环节。
- 首版不优先对接外部企业系统，但会预留接口。

#### A. 文档生成

- 支持按文档类型选择模板并生成初稿。
- 支持引用规范、历史文档、术语库进行检索增强生成。
- 支持章节级重写、续写、润色、术语纠偏。
- 支持导出 Word / Markdown / PDF。

#### B. 文档审查

- 支持上传现有文档进行解析和审查。
- 支持 GJB 章节完整性、编号、格式、术语、图表规范校验。
- 支持基于大模型的内容缺失、表达歧义、逻辑冲突、测试覆盖不足提示。
- 支持问题分级、定位、引用规则来源、给出整改建议。

#### C. 一致性检查

- 支持需求-设计-测试三类文档之间的术语一致性检查。
- 支持接口名称、模块名称、版本信息、编号引用一致性检查。
- 支持跨版本文档差异比对。

#### D. 整改闭环

- 支持问题确认、驳回、整改、复核状态流转。
- 支持生成审查报告。
- 支持保留问题处理审计记录。

#### E. 知识底座

- 支持导入规则、模板、术语库、历史文档、历史审查意见。
- 支持按文档类型管理知识资产。
- 支持知识版本更新与启停。

#### F. 用户手册能力

- 支持上传截图批量生成步骤说明。
- 支持通过 Electron 客户端调用桌面截图能力采集手册素材。
- 支持按章节结构生成用户手册初稿。
- 支持统一术语和界面要素命名。

### 5.2 二期增强功能

- 自动驱动目标软件界面完成步骤执行、截图采集并生成手册。
- 自动生成 UML 类图、流程图、时序图草稿。
- 支持更细粒度工作流审批。
- 支持更多安全审计与密级管理策略。
- 支持对接现有项目管理系统或配置管理系统。

## 六、Architecture Plan

### 6.1 逻辑架构

建议采用五层架构：

1. 表现层
- Electron 客户端；
- Vue 业务前端；
- 审查结果可视化；
- 配置与管理后台。

2. 应用层
- 文档生成服务；
- 文档审查服务；
- 知识管理服务；
- 模型配置服务；
- 任务流转服务。

3. 领域层
- 模型网关；
- 规则引擎；
- 审查编排器；
- 生成编排器；
- 一致性检查器；
- 手册生成器。

4. 资源层
- 文档解析服务；
- OCR；
- 向量检索；
- 术语库；
- 模板库；
- 历史文档索引。

5. 基础设施层
- PostgreSQL；
- 对象存储；
- 向量数据库；
- 任务队列；
- 日志/审计。

### 6.2 客户端分层

- 主进程：
  - 窗口管理；
  - 桌面截图；
  - 本地文件系统；
  - 安装包升级；
  - 本地配置读写。
- 预加载层：
  - 受控暴露桌面 API；
  - IPC 参数校验；
  - 桥接前端与主进程。
- 渲染层：
  - Vue 页面；
  - Ant Design Vue 组件；
  - 业务状态管理；
  - 后端 API 调用。

### 6.3 关键数据流

#### 生成链路

1. 用户选择文档类型与模板。
2. 系统检索规范、术语、历史文档片段。
3. 模型生成章节草稿。
4. 规则引擎执行模板/GJB 初审。
5. 审查编排器输出问题清单与修订建议。
6. 用户修订后导出或提交复核。

#### 审查链路

1. 用户上传现有文档。
2. 解析服务抽取章节、表格、图片、批注和编号。
3. 规则引擎执行硬规则检查。
4. 大模型执行语义完整性与可读性检查。
5. 一致性检查器执行跨文档/跨章节核验。
6. 聚合问题清单并生成审查报告。

#### 截图与手册链路

1. 用户在 Electron 客户端发起截图任务。
2. 主进程调用桌面截图服务完成全屏、窗口或区域采集。
3. 截图文件与元数据传递给渲染层并上传到后端。
4. 手册生成模块结合截图顺序、界面元素标注与术语库生成操作说明。
5. 用户在客户端中修订后导出手册。

### 6.4 模型接入方案

- 默认使用本地 32B 主模型。
- 通过模型网关兼容：
  - Ollama；
  - OpenAI 兼容 API；
  - DeepSeek 兼容接口；
  - 后续其他本地推理框架。
- 所有模型调用统一记录：
  - 调用来源；
  - 输入摘要；
  - 输出摘要；
  - 时延；
  - 错误信息；
  - 模型版本。

### 6.5 规则引擎方案

- 规则采用 YAML/JSON 配置化存储。
- 支持规则版本管理。
- 支持按文档类型启用不同规则集合。
- 支持规则严重级别定义。
- 支持规则结果映射为统一问题对象，供前端展示和整改流转。

## 八、Acceptance Criteria

首版验收建议至少满足以下标准：

### 8.1 功能验收

- 可上传并解析至少 4 类以上文档类型。
- 可基于模板生成文档初稿。
- 可对生成文档或现有文档执行 GJB 规则审查。
- 可输出结构化问题清单，包含规则来源、严重级别、定位、整改建议。
- 可执行至少一类跨文档一致性检查。
- 可导入知识资产并用于生成/审查增强。
- 可基于截图生成用户手册说明。

### 8.2 工程验收

- 支持本地部署与离线运行。
- 支持打包为可安装的 Electron 客户端。
- 模型接入可切换，不与单一供应方绑定。
- 规则库可配置，可独立更新。
- 审查流程具有审计日志。
- 支持基础权限区分：普通用户、审查专家、管理员。

### 8.3 演示验收

- 可完成“导入规范 -> 生成文档 -> 自动审查 -> 整改复核 -> 导出报告”的完整演示链路。
- 可展示规则命中与语义审查差异化效果。
- 可展示知识底座对生成质量和术语统一性的提升。

## 九、Risks And Mitigations

### 风险 1：Word/PDF 复杂格式解析不稳定

应对：
- 首版优先标准模板文档；
- 建立标准化中间表示；
- 对异常结构保留人工确认入口。

### 风险 2：规则覆盖不足导致审查结果不稳定

应对：
- 首版选取高频高价值规则；
- 规则版本化；
- 通过历史审查意见反哺规则库。

### 风险 3：大模型在涉密环境下性能或效果不足

应对：
- 采用主模型 + 检索增强 + 规则兜底；
- 保留模型切换与参数调优能力；
- 对长文档采用分段处理与任务编排。

### 风险 4：跨文档一致性检查复杂度高

应对：
- 首版先聚焦术语、模块名、接口名、编号映射；
- 后续逐步扩展到需求-设计-测试追踪矩阵。

### 风险 5：Electron 客户端权限边界处理不当

应对：
- 使用 preload 暴露受控 API，禁用渲染进程直接访问 Node 高权限能力；
- 对截图、文件读写、导出等操作增加白名单与参数校验；
- 关键桌面操作记录审计日志。

## 十、Verification Steps

后续执行阶段按以下顺序验证：

1. 基础环境验证
- Electron 客户端、前后端工程可启动；
- 数据库、对象存储、向量库、模型网关连接成功。

2. 知识底座验证
- 能导入规范、模板、术语、历史文档；
- 能完成索引并成功检索相关片段。

3. 生成链路验证
- 指定模板后能生成结构完整的文档初稿；
- 输出内容能引用术语库与规范片段；
- 能导出标准格式文件。

4. 审查链路验证
- 能解析样例文档；
- 能命中规则问题；
- 能生成语义问题与整改建议；
- 能输出审查报告。

5. 闭环验证
- 问题可确认、整改、复核；
- 状态流转正确；
- 留存审计记录。

6. 一致性与手册验证
- 可检查至少一个项目下多份文档的一致性；
- 可通过 Electron 采集截图并生成手册段落和操作步骤。

7. 演示验证
- 能完成 10 分钟内稳定演示；
- 展示首版闭环价值与后续扩展空间。

## 十一、Recommended Execution Order

如果进入执行阶段，建议严格按以下顺序推进：

1. 初始化工程骨架与部署底座。
2. 建立模型网关和配置化接入机制。
3. 实现知识资产导入与文档解析。
4. 实现规则引擎与规则配置加载。
5. 实现文档生成功能。
6. 实现文档审查和问题清单。
7. 打通生成即审查闭环。
8. 实现一致性检查。
9. 实现截图说明与用户手册生成。
10. 完成验收清单、演示数据和部署文档。

该顺序可以确保最早获得可演示能力，同时避免在高级功能完成前缺失底层支撑能力。
